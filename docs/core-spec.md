# coffee-core — спецификация интерфейса общего ядра

Статус: черновик v0.1 · Ядро: Rust · Доставка: WebAssembly (основной путь), C ABI (опционально)

Документ описывает **границу** между общим ядром и обёртками для языков (Go, Python, JS/TS):
операции, формат обмена, вызовы хоста, ошибки, лимиты и правила совместимости.
Семантика шаблонов (синтаксис, правила раскрытия циклов, фильтры, модель документа) нормативно
определяется текущей TS-реализацией `coffee-templater` и её тестами. Где эта спецификация молчит,
поведение должно совпадать с TS-версией.

---

## 1. Принципы

1. **Чистые функции.** Ядро не делает I/O: нет файловой системы, сети, часов, переменных окружения.
   Всё, что нужно, приходит во входных данных.
2. **Байты и JSON на границе.** Вход и выход — UTF-8 JSON и бинарные блобы. Никаких указателей на
   объекты хоста и никаких языковых типов.
3. **Детерминизм.** Одинаковый вход даёт побайтно одинаковый выход на любом хосте: фиксированный
   порядок записей ZIP, фиксированные метки времени, фиксированный уровень сжатия.
4. **Один экспорт — один диспетчер.** ABI состоит из нескольких функций, новые операции добавляются
   без изменения ABI.
5. **Безопасность по умолчанию.** Входные документы недоверенные: включены лимиты от zip-бомб,
   глубокого XML и бесконечного вывода; DTD и внешние сущности не обрабатываются.
6. **Обёртки тонкие.** Логика целиком живёт в ядре. Обёртка отвечает за идиоматичный API,
   конвертацию значений, вызов пользовательских функций и преобразование ошибок.

## 2. Архитектура

```
coffee-core/                 (отдельный репозиторий)
├── crates/core              Rust: шаблонизатор, модель, OPC/ZIP/XML — без зависимостей от ABI
├── crates/abi               кадры сообщений, диспетчер операций, вызовы хоста
├── crates/wasm              cdylib → coffee_core.wasm (wasm32-unknown-unknown)
├── crates/capi  (опц.)      cdylib/staticlib + coffee_core.h — для нативных сборок
├── schema/                  JSON Schema модели, inspect-результата, опций, ошибок (генерируется)
└── conformance/             языконезависимые тест-кейсы (раздел 11)

Обёртки (отдельные пакеты, могут жить в монорепо):
├── go/       модуль Go, wazero, coffee_core.wasm через go:embed
├── python/   пакет, wasmtime, wheel py3-none-any с .wasm внутри
└── js/       npm-пакет (WASM) — или текущая TS-реализация как отдельная ветка
```

Артефакт ядра — один файл `coffee_core.wasm`, общий для всех языков и платформ.

## 3. Логические операции

| Операция      | Вход                                         | Выход                                      |
| ------------- | -------------------------------------------- | ------------------------------------------ |
| `info`        | —                                            | версии, форматы, возможности               |
| `compile`     | шаблон (блоб), `options`                     | `template` (хэндл), `format`, `warnings`   |
| `render`      | `template`, `data` (+ блобы данных)          | документ (блоб)                            |
| `renderOnce`  | шаблон (блоб), `options`, `data`             | документ (блоб)                            |
| `inspect`     | `template`                                   | `InspectResult`                            |
| `dispose`     | `template`                                   | —                                          |
| `parse`       | документ (блоб), `limits?`                   | модель документа (JSON)                    |
| `build`       | модель (JSON), `base` (блоб, опц.)           | документ (блоб)                            |
| `extractText` | документ (блоб)                              | `{ text }`                                 |
| `detect`      | документ (блоб)                              | `{ format }`                               |

Хэндл `template` — целое число, уникальное в пределах **одного экземпляра** ядра (см. раздел 9).

## 4. Формат обмена: кадр (frame)

Каждый запрос и ответ — один **кадр**: JSON-заголовок и список бинарных блобов.
Все целые числа — `u32`, little-endian. Выравнивание не требуется.

```
offset  size   поле
0       4      magic = "CTF1" (0x43 0x54 0x46 0x31)
4       4      json_len
8       N      JSON (UTF-8, без BOM)
8+N     4      blob_count
...            повторить blob_count раз:
        4        blob_len
        M        байты блоба
```

Блобы адресуются в JSON по индексу: `{"$blob": 0}`. Блобы нужны, чтобы не гонять документы и
картинки через base64.

### 4.1 Запрос

```json
{ "op": "render", "id": 17, "template": 3, "data": { "name": "Ann", "logo": { "data": { "$blob": 0 } } } }
```

- `op` — имя операции (обязательно).
- `id` — необязательный идентификатор запроса, возвращается в ответе (для логов и трассировки).
- Остальные поля зависят от операции (раздел 6).

### 4.2 Ответ

Успех:

```json
{ "ok": true, "id": 17, "result": { "document": { "$blob": 0 } }, "warnings": [] }
```

Ошибка:

```json
{ "ok": false, "id": 17, "errors": [ { "code": "unclosed_section", "message": "...", "part": "word/document.xml", "tag": "{{#items}}" } ] }
```

Структура ошибки описана в разделе 8.

## 5. Значения данных (`data`)

Данные шаблона — обычный JSON плюс **тегированные значения**: объекты ровно с одним ключом из
списка ниже. Они выражают то, чего в JSON нет.

| Тег                         | Значение в ядре             | Пример                                      |
| --------------------------- | --------------------------- | ------------------------------------------- |
| `{"$date": "<ISO 8601>"}`   | дата/время                  | `{"$date": "2024-05-17T10:00:00Z"}`, `{"$date": "2024-05-17"}` |
| `{"$decimal": "<строка>"}`  | точное десятичное число     | `{"$decimal": "1234.50"}` — деньги, Go `big.Rat`/`decimal`, Python `Decimal` |
| `{"$blob": <index>}`        | байты из блоба запроса      | картинки                                    |
| `{"$base64": "<строка>"}`   | байты из base64 / data-URL  | для хостов, которым неудобны блобы          |
| `{"$literal": <любое>}`     | значение как есть, без разбора тегов | `{"$literal": {"$date": "не дата"}}`   |

Правила:

- Объект считается тегом, только если у него **ровно один ключ** и ключ — из таблицы. Иначе это
  обычный объект.
- Даты без часового пояса трактуются как «наивные» (как в Excel). Даты с поясом нормализуются в UTC.
- **Числа JSON.** Ядро хранит исходную лексему числа. Если число выводится без фильтров, печатается
  исходная лексема: `12345678901234567890` не превращается в `1.2345678901234567e19`. Для
  арифметики и фильтров используется `f64`, а для `$decimal` — десятичная арифметика.
- Картинка — объект `ImageValue` из TS-версии, у которого `data` — `$blob` или `$base64`:
  `{"data": {"$blob": 0}, "width": 120, "height": 60, "extension": "png", "alt": "Logo"}`.

### Конвертация на стороне хоста (рекомендации для обёрток)

| Хост     | → JSON                                                                                   |
| -------- | ---------------------------------------------------------------------------------------- |
| Go       | `encoding/json` с учётом тегов `json:"..."`; `time.Time` → `$date`; `[]byte` → `$blob`; `decimal.Decimal`/`*big.Rat` → `$decimal` |
| Python   | dict / list / dataclass / pydantic-модели / Mapping; `datetime`/`date` → `$date`; `bytes` → `$blob`; `Decimal` → `$decimal` |
| JS/TS    | обычные объекты; `Date` → `$date`; `Uint8Array`/`Buffer`/`ArrayBuffer` → `$blob`; `bigint` → число-лексема |

Ленивых геттеров нет: данные передаются целиком. Это осознанное ограничение (см. раздел 13).

## 6. Операции: схемы запросов и ответов

### 6.1 `info`

Запрос: `{"op": "info"}`

```json
{
  "coreVersion": "0.1.0",
  "abiVersion": 1,
  "modelVersion": 1,
  "formats": ["docx", "xlsx", "pptx"],
  "features": { "images": ["docx", "pptx"], "slideLoops": false, "hostFilters": true }
}
```

Обёртка вызывает `info` при инициализации и проверяет, что `abiVersion` поддерживается.

### 6.2 `compile`

```json
{ "op": "compile", "template": { "$blob": 0 }, "options": { ... } }
```

`options` (все поля необязательны, значения по умолчанию — как в TS):

```json
{
  "delimiters": { "start": "{{", "end": "}}" },
  "escapeChar": "\\",
  "syntax": { "section": "#", "inverted": "^", "close": "/", "image": "%", "else": "else", "if": "if", "unless": "unless", "each": "each" },
  "strict": false,
  "linebreaks": true,
  "hostFilters": ["money", "phone"],
  "nullValue": { "mode": "empty" },
  "stringify": { "mode": "default", "dateFormat": "iso" },
  "limits": { ... }
}
```

- `escapeChar: null` отключает экранирование.
- `hostFilters` — имена фильтров, реализованных на стороне хоста (раздел 7). Объявляются при
  компиляции, чтобы ошибку `unknown_filter` можно было выдать сразу. Имя хост-фильтра перекрывает
  встроенный фильтр с тем же именем.
- `nullValue.mode` — что делать с `undefined`/`null`:
  - `"empty"` — пустая строка (по умолчанию);
  - `"text"` — строка из `nullValue.text`;
  - `"keep"` — оставить исходный текст тега;
  - `"host"` — спросить хост (раздел 7);
  - `"error"` — то же, что `strict: true`.
- `stringify.mode`: `"default"` — правила TS-версии; `"host"` — нестроковые значения
  форматирует хост.
- `limits` — раздел 10.

Ответ:

```json
{ "template": 3, "format": "docx", "parts": ["word/document.xml", "word/header1.xml"] }
```

**Ошибки шаблона собираются списком**, а не по первой: `errors[]` содержит все найденные проблемы
(это отличие от TS-версии, которая бросает первую ошибку).

### 6.3 `render`

```json
{ "op": "render", "template": 3, "data": { ... } }
```

Блобы, на которые ссылается `data`, передаются в этом же кадре.

Ответ: `{"document": {"$blob": 0}}`, документ — в блобе 0 ответа.

### 6.4 `renderOnce`

`compile` + `render` + `dispose` за один вызов: `{"op": "renderOnce", "template": {"$blob": 0}, "options": {...}, "data": {...}}`.

### 6.5 `inspect`

`{"op": "inspect", "template": 3}` → `InspectResult` из TS-версии:
`format`, `parts[]`, `tags[]` (дерево), `variables[]` (`items[].name`), `schema` (пример данных).

### 6.6 `dispose`

`{"op": "dispose", "template": 3}` → `{}`. Повторный `dispose` и неизвестный хэндл — не ошибка.

### 6.7 `parse`

```json
{ "op": "parse", "document": { "$blob": 0 }, "limits": { ... } }
```

Ответ: модель документа (`DocxDocument | XlsxDocument | PptxDocument`) с полем `modelVersion`.

```json
{ "model": { "format": "docx", "modelVersion": 1, "parts": [ ... ] } }
```

### 6.8 `build`

```json
{ "op": "build", "model": { ... }, "base": { "$blob": 0 } }
```

`base` необязателен для docx/xlsx и обязателен для pptx. Ответ: `{"document": {"$blob": 0}}`.

### 6.9 `extractText`, `detect`

`{"op": "extractText", "document": {"$blob": 0}}` → `{"text": "..."}`
`{"op": "detect", "document": {"$blob": 0}}` → `{"format": "xlsx"}`

## 7. Вызовы хоста (callbacks)

Пользовательские фильтры, `nullValue: host` и `stringify: host` выполняются на стороне хоста.
Ядро вызывает **одну** импортируемую функцию и передаёт кадр.

Запрос от ядра к хосту:

```json
{ "call": "filter", "name": "money", "value": 1250.5, "args": ["RUB"], "tag": { "raw": "{{total | money: \"RUB\"}}", "part": "word/document.xml" } }
{ "call": "nullValue", "tag": { "raw": "{{client.phone}}", "expression": "client.phone", "part": "word/document.xml" } }
{ "call": "stringify", "value": { "$date": "2024-05-17" }, "tag": { ... } }
```

Значения передаются в той же нотации, что `data` (раздел 5), включая блобы.

Ответ хоста:

```json
{ "ok": true, "value": "1 250,50 ₽" }
{ "ok": false, "message": "unsupported currency" }
```

Правила:

- Вызов синхронный. Во время callback хост **не должен** вызывать операции того же экземпляра
  ядра; разрешены только `ct_alloc`/`ct_free` (см. ABI).
- `ok: false` превращается в ошибку `filter_failed` (или `host_error` для остальных вызовов),
  сообщение хоста сохраняется в `details.hostMessage`.
- Исключение или паника в хосте ловятся обёрткой и возвращаются как `ok: false`.
- Хост-фильтр может вернуть любое значение (строку, число, массив, объект), а не только строку:
  фильтры используются в условиях и циклах (`{{#each items | myFilter}}`).

## 8. Ошибки

```json
{
  "code": "unclosed_section",
  "message": "Section is never closed",
  "part": "word/document.xml",
  "tag": "{{#items}}",
  "location": { "paragraph": 12 },
  "details": {}
}
```

Коды ошибок шаблона (как в TS): `unclosed_tag`, `unopened_tag`, `unclosed_section`, `unmatched_close`,
`invalid_expression`, `unknown_filter`, `filter_failed`, `missing_value`, `invalid_section`,
`invalid_image`, `unsupported`.

Коды уровня ядра:

| Код                  | Когда                                                         |
| -------------------- | ------------------------------------------------------------- |
| `invalid_request`    | битый кадр, неизвестная операция, неверные поля запроса       |
| `invalid_options`    | некорректные опции (пустые или одинаковые разделители и т.п.) |
| `invalid_document`   | не ZIP, нет `[Content_Types].xml`, битый XML                  |
| `unsupported_format` | не docx/xlsx/pptx                                             |
| `invalid_model`      | модель не соответствует схеме или ссылается на несуществующие части |
| `unknown_template`   | хэндл не найден или уже освобождён                            |
| `limit_exceeded`     | превышен лимит (раздел 10), в `details` — какой именно        |
| `host_error`         | callback хоста вернул ошибку или неверный ответ               |
| `internal`           | паника или ошибка в ядре: баг, должен сопровождаться issue    |

`location` необязателен и заполняется по возможности: `paragraph`, `cell` (`"B12"`), `slide`, `row`.

Обёртки маппят ошибки идиоматично: Go — `*coffee.Error` с полями и `errors.Is` по коду;
Python — `TemplateError(Exception)` с атрибутами и подклассами по группам; JS — `TemplateError`.

`warnings[]` в ответе имеют тот же формат с кодами вида `deprecated_syntax`, `image_unsupported_in_format`
и т.п.: они не прерывают операцию.

## 9. ABI

### 9.1 WebAssembly (основной путь)

Модуль: `wasm32-unknown-unknown`, без WASI. Экспорт линейной памяти `memory`.

Экспорты:

| Функция                                  | Назначение                                                        |
| ---------------------------------------- | ----------------------------------------------------------------- |
| `ct_abi_version() -> u32`                | версия ABI (сейчас `1`)                                           |
| `ct_alloc(len: u32) -> u32`              | выделить `len` байт в памяти модуля, вернуть указатель (0 — ошибка) |
| `ct_free(ptr: u32, len: u32)`            | освободить память, выделенную `ct_alloc` или полученную от ядра   |
| `ct_call(req_ptr: u32, req_len: u32) -> u32` | выполнить запрос (кадр); вернуть указатель на ответ           |

Ответ `ct_call` лежит по адресу `ptr` в виде `[u32 frame_len][кадр]`. Хост читает
`frame_len`, копирует кадр и освобождает память: `ct_free(ptr, frame_len + 4)`.
Буфер запроса хост выделяет через `ct_alloc` и освобождает сам после `ct_call`.

Импорт (модуль `ct_host`):

| Функция                                   | Назначение                                                      |
| ----------------------------------------- | --------------------------------------------------------------- |
| `call(req_ptr: u32, req_len: u32) -> u32` | callback (раздел 7)                                              |

Хост читает кадр запроса из памяти, выполняет callback, выделяет ответ через `ct_alloc`,
записывает `[u32 frame_len][кадр]` и возвращает указатель. Ядро освобождает его само.
Возврат `0` означает «хост не поддерживает callbacks», и ядро возвращает ошибку `host_error`.

Если ни одна возможность хоста не используется (`hostFilters` пуст, режимы не `host`), импорт
не вызывается никогда. Хост всё равно обязан его предоставить (заглушка, возвращающая 0).

### 9.2 C ABI (опционально, для нативных сборок)

```c
uint32_t ct_abi_version(void);
typedef struct { const uint8_t* ptr; size_t len; } ct_bytes;
typedef ct_bytes (*ct_host_fn)(void* user_data, ct_bytes request);   // ответ выделен через ct_alloc
void*    ct_instance_new(ct_host_fn host, void* user_data);
void     ct_instance_free(void* instance);
ct_bytes ct_call(void* instance, ct_bytes request);                 // освобождать через ct_free
uint8_t* ct_alloc(size_t len);
void     ct_free(uint8_t* ptr, size_t len);
```

Кадры и семантика такие же, как в WASM. Отличие одно: экземпляр явный (`ct_instance_new`),
поэтому callback привязан к экземпляру через `user_data`.

### 9.3 Экземпляры, потоки, хэндлы

- Экземпляр WASM-модуля **однопоточный**. Параллельность обеспечивает обёртка пулом экземпляров
  (Go: `sync.Pool` поверх wazero `CompiledModule` → `InstantiateModule`; Python: пул на поток или
  `threading.local`).
- Хэндлы шаблонов живут внутри конкретного экземпляра. Поэтому объект `Template` в обёртке хранит
  исходные байты и опции и **лениво компилирует** шаблон в каждом экземпляре пула, кэшируя хэндл.
  Кэш сбрасывается при уничтожении экземпляра.
- Обёртка обязана вызывать `dispose` (Go: `Close()`, Python: контекстный менеджер / `__del__` /
  finalizer, JS: `FinalizationRegistry` + явный `dispose()`).
- Отмена и таймауты: Go — `context.Context` (wazero `WithCloseOnContextDone`); Python — epoch
  interruption в wasmtime. После прерывания экземпляр выбрасывается из пула.
- Память wasm32 ограничена 4 ГБ на экземпляр, практический предел документа — сотни мегабайт
  (и так ограничен лимитами).

## 10. Лимиты (безопасность)

Передаются в `options.limits` или `parse.limits`. Значения по умолчанию консервативные, `0` — без ограничения.

| Лимит                   | По умолчанию | Смысл                                             |
| ----------------------- | ------------ | ------------------------------------------------- |
| `maxInputBytes`         | 100 MiB      | размер входного файла                             |
| `maxEntries`            | 10 000       | число записей в ZIP                               |
| `maxUncompressedBytes`  | 500 MiB      | суммарный распакованный размер                    |
| `maxCompressionRatio`   | 200          | отношение распакованного к сжатому (zip-бомбы)    |
| `maxXmlDepth`           | 256          | глубина вложенности XML                           |
| `maxOutputBytes`        | 500 MiB      | размер результата до сжатия                       |
| `maxLoopIterations`     | 1 000 000    | суммарное число итераций всех циклов при рендере  |
| `maxHostCalls`          | 1 000 000    | число callbacks за операцию                       |

Дополнительно, всегда и без настроек:

- `<!DOCTYPE>` и внешние сущности не разворачиваются: только 5 стандартных сущностей и
  числовые ссылки.
- Пути в ZIP с `..`, абсолютные пути и дубликаты имён отклоняются (`invalid_document`).
- Свойства прототипа и служебные ключи в данных недоступны из выражений (как в TS).

## 11. Conformance-набор (общие тесты)

Языконезависимые кейсы. Их прогоняют ядро (Rust) и каждая обёртка.

```
conformance/
├── fixtures/                      шаблоны (.docx/.xlsx/.pptx) + generate.py
```

`case.json`:

```json
{
  "op": "render",
  "template": "fixtures/invoice.docx",
  "options": { "delimiters": { "start": "{{", "end": "}}" } },
  "hostFilters": { "money": { "type": "format", "pattern": "{value} {arg0}" } },
  "expect": {
    "text": "Invoice 42\nClient: Иван\n...",
    "model": { "path": "parts[0].blocks[1]", "equals": { "type": "paragraph" } },
    "parts": { "word/document.xml": { "contains": ["<w:br/>"], "notContains": ["{{"] } },
    "sha256": "…"
  }
}
```

или для ошибок:

```json
{ "op": "compile", "template": "fixtures/broken.docx", "expect": { "errors": [ { "code": "unclosed_section", "tag": "{{#items}}" } ] } }
```

- Проверки идут от устойчивых к строгим: `text` (через `extractText`) → `model` (через `parse`)
  → `parts` (подстроки XML) → `sha256`. Из-за детерминизма (раздел 12) `sha256` одинаков на всех
  хостах и ловит любые расхождения обёрток.
- `hostFilters` в кейсах описываются декларативно (простые типы: `format`, `upper`, `throw`),
  чтобы каждая обёртка реализовала их тривиально.
- Основа набора — текущие 69 тестов и фикстуры TS-версии.

## 12. Детерминизм выхода

- Порядок записей ZIP: как во входном файле, новые записи добавляются в конец в порядке создания.
- Метка времени всех записей: `1980-01-01 00:00:00`.
- Сжатие: deflate фиксированным уровнем 6 одной и той же реализацией (она внутри `.wasm`, поэтому
  совпадает на всех хостах).
- Имена новых медиафайлов и id связей генерируются счётчиками, без случайности.
- Сериализация JSON-ответов: порядок ключей фиксирован (как в схеме), без лишних пробелов.

## 13. Версионирование и совместимость

| Версия          | Где                   | Когда растёт                                                   |
| --------------- | --------------------- | -------------------------------------------------------------- |
| `abiVersion`    | `ct_abi_version`      | меняются экспорты/импорты или формат кадра (ломающее)          |
| `coreVersion`   | `info`                | semver ядра                                                    |
| `modelVersion`  | в модели и `info`     | ломающие изменения JSON-модели                                 |

- Новые операции, новые необязательные поля запросов и ответов, новые коды ошибок и предупреждений —
  **не ломающие**. Обёртки обязаны игнорировать неизвестные поля ответа.
- `build` принимает модели текущей и предыдущей `modelVersion`.
- JSON Schema (`schema/*.json`) генерируется из Rust-типов (`schemars`) и публикуется вместе с ядром.
  Из неё генерируются типы обёрток: Go-структуры, Python `TypedDict`/pydantic, TS-типы.

Осознанные ограничения v1:

- Нет ленивых данных и геттеров: данные сериализуются целиком.
- Нет асинхронных хост-фильтров: вызовы синхронные.
- Нет стриминга: документ целиком в памяти.

## 14. Рекомендуемый API обёрток (для единообразия)

Сигнатуры даны как ориентир, имена — в стиле языка.

| Возможность        | Go                                                     | Python                                         | JS/TS                                   |
| ------------------ | ------------------------------------------------------ | ---------------------------------------------- | --------------------------------------- |
| Создать            | `coffee.New(coffee.Options{...})`                      | `Templater(delimiters=("{{","}}"), filters={...})` | `createTemplater({...})`            |
| Скомпилировать     | `t.Compile(tpl []byte) (*Template, error)`             | `t.compile(data: bytes) -> Template`           | `t.compile(bytes)`                      |
| Рендер             | `tpl.Render(ctx, data any) ([]byte, error)`            | `tpl.render(data) -> bytes`                    | `tpl.render(data)`                      |
| Инспекция          | `tpl.Inspect() (*InspectResult, error)`                | `tpl.inspect() -> InspectResult`               | `tpl.inspect()`                         |
| Освобождение       | `tpl.Close()`                                          | `with t.compile(...) as tpl:` / `tpl.close()`  | `tpl.dispose()`                         |
| Модель             | `coffee.Parse(doc) (Document, error)` / `coffee.Build(model, base)` | `parse(doc)` / `build(model, base=...)` | `parse` / `build`                |
| Фильтры            | `Filters: map[string]coffee.FilterFunc`                | `filters={"money": fn}`                        | `filters: { money: fn }`                |

`FilterFunc` получает значение и аргументы, уже сконвертированные в типы языка (`time.Time`,
`datetime`, `Date`, `Decimal`, …), и возвращает значение языка. Конвертацию делает обёртка.

## 15. Открытые вопросы (решить до v1)

1. Пул экземпляров по умолчанию: размер, политика (на поток или общий), прогрев.
2. `$decimal`: какую десятичную арифметику брать в ядре (`rust_decimal` и её точность) и как фильтры
   `number`/`currency` форматируют `$decimal` без потери точности.
3. Локализация встроенных фильтров (`currency`, `date`): своя мини-ICU-таблица в ядре или
   `stringify: host` для локалей.
4. Оставлять ли TS-версию отдельной реализацией (без WASM, лучше для браузера) или перевести npm-пакет
   на ядро. Во втором случае conformance-набор гарантирует идентичность.
5. Нужен ли нативный путь для Python (PyO3) сразу или только после замеров.
6. Лицензия ядра и обёрток (MIT, как у TS-версии) и название крейта/модулей.
