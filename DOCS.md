# coffee-templater — документация

Подробное руководство на русском. Краткий обзор на английском — в [README.md](README.md).

Вся работа с документами выполняется ядром
[coffee-templater-engine](https://github.com/vitJR1/coffee-templater-engine) (Rust → WebAssembly).
Оно встроено в пакет: отдельно ничего ставить не нужно. Эта библиотека — JS/TS-обёртка над ним.

## 1. Установка и требования

```bash
npm install coffee-templater
```

- Node.js ≥ 18 или любой современный браузер. Нативных зависимостей нет: ядро — это WebAssembly,
  встроенный в бандл (около 380 КБ в сжатом виде). Единственная JS-зависимость —
  [`fflate`](https://github.com/101arrowz/fflate), им ядро распаковывается при первом вызове.
- Пакет поставляется в ESM и CommonJS, типы TypeScript включены.
- На вход принимаются `Uint8Array`, `Buffer`, `ArrayBuffer` и любые `ArrayBufferView`.
  На выходе всегда `Uint8Array`.

## 2. Быстрый старт

```ts
import { readFileSync, writeFileSync } from 'node:fs'
import { createTemplater } from 'coffee-templater'

const templater = createTemplater()

const result = templater.render(readFileSync('invoice.docx'), {
  number: 42,
  client: { name: 'Иван Петров' },
  items: [
    { name: 'Кофе', qty: 2, price: 10.5 },
    { name: 'Чай', qty: 1, price: 4 },
  ],
  paid: false,
})

writeFileSync('invoice-42.docx', result)
```

Формат (`.docx`, `.xlsx`, `.pptx`) определяется по содержимому файла, расширение не важно.

### Скомпилировать один раз, рендерить много раз

Разбор шаблона — самая дорогая часть. Если по одному шаблону генерируется много документов,
компилируйте его один раз:

```ts
const template = templater.compile(readFileSync('invoice.docx'))

for (const invoice of invoices) {
  writeFileSync(`invoice-${invoice.number}.docx`, template.render(invoice))
}
```

Объект `Template` неизменяем, и каждый `render()` работает с собственной копией документа,
поэтому один шаблон можно безопасно использовать для любого числа рендеров.

### В браузере

```ts
import { initEngine, createTemplater } from 'coffee-templater'

await initEngine() // необязательно: асинхронно компилирует ядро, не блокируя основной поток

const file = await fetch('/templates/invoice.docx').then((r) => r.arrayBuffer())
const bytes = createTemplater().render(file, data)
const url = URL.createObjectURL(new Blob([bytes]))
```

## 3. Синтаксис шаблонов

Теги пишутся прямо в тексте документа в Word, Excel или PowerPoint. Разделители по умолчанию —
`{{` и `}}`, их можно поменять (раздел 10).

### Переменные

| Тег | Что выводит |
| --- | --- |
| `{{name}}` | поле `name` |
| `{{client.address.city}}` | вложенное поле |
| `{{items[0].name}}`, `{{items[-1].name}}` | элемент массива по индексу, отрицательный — с конца |
| `{{map["ключ с пробелами"]}}` | поле с произвольным именем |
| `{{list.length}}` | длина массива или строки |
| `{{имя_клиента}}` | кириллица в именах допустима |

Значения выводятся так:

| Значение | Результат |
| --- | --- |
| строка | как есть (XML-символы экранируются автоматически) |
| число, boolean | `String(value)` |
| `Date` | ISO-строка; для своего формата используйте фильтр `date` |
| массив | элементы через `, ` |
| объект | `JSON.stringify`, либо его `toString()`, если он переопределён |
| `undefined` / `null` | результат `nullGetter` (по умолчанию пустая строка) |

Перевод строки `\n` в значении становится настоящим переносом строки в документе, `\t` — табуляцией
(в Word). Отключается опцией `linebreaks: false`.

### Секции

| Тег | Назначение |
| --- | --- |
| `{{#items}}…{{/items}}` | массив — цикл; объект — смена контекста; иначе — условие по истинности |
| `{{#each items}}…{{/each}}` | явный цикл; для объектов перебирает значения, ключ — в `{{@key}}` |
| `{{#if paid}}…{{/if}}` | условие |
| `{{#unless paid}}…{{/unless}}` | условие «если нет» |
| `{{^items}}…{{/items}}` | инвертированная секция: рендерится, если значение пустое/ложное |
| `{{else}}` | ветка «иначе» в любой секции |
| `{{/}}` | закрывает ближайшую открытую секцию |

Истинность: пустой массив ложен, непустой истинен; остальное — по правилам JavaScript
(`0`, `''`, `null`, `undefined`, `false` ложны; строка `"0"` истинна).

### Внутри цикла

| Выражение | Значение |
| --- | --- |
| `{{.}}` или `{{this}}` | текущий элемент |
| `{{name}}` | поле текущего элемента; если его нет — ищется во внешних областях |
| `{{../title}}` | значение из родительской области (`../../x` — на два уровня выше) |
| `{{@index}}` | номер элемента с нуля |
| `{{@number}}` | номер элемента с единицы |
| `{{@first}}`, `{{@last}}` | первый / последний элемент |
| `{{@length}}` | длина перебираемого массива |
| `{{@key}}` | ключ (в `#each` по объекту) |

Пример — список через запятую с точкой в конце:

```
{{#items}}{{name}}{{#@last}}.{{/@last}}{{^@last}}, {{/@last}}{{/items}}
```

### Строковые литералы

Аргументы фильтров можно писать в любых кавычках: `"…"`, `'…'`, а также в типографских `“…”`,
`«…»`, `‘…’`, которые Word подставляет автоматически при наборе. Числа: `42`, `-1.5`.
Ключевые слова: `true`, `false`, `null`.

## 4. Циклы: что именно повторяется

Главный вопрос любого Office-шаблонизатора — что дублировать: текст, абзац или строку таблицы.
coffee-templater решает это **по положению открывающего и закрывающего тегов**:

| Где стоят теги | Что повторяется |
| --- | --- |
| в одном абзаце (или одной ячейке Excel) | текст между тегами |
| каждый тег один в своём абзаце | абзацы между ними, сами абзацы с тегами удаляются |
| в разных ячейках одной строки таблицы (Word, PowerPoint) | вся строка таблицы |
| в разных ячейках одной строки листа (Excel) | вся строка листа |
| в разных строках таблицы или листа | диапазон строк от первой до последней |

### Повтор текста внутри абзаца

```
Теги: {{#tags}}[{{.}}] {{/tags}}
```
→ `Теги: [кофе] [чай]`

### Повтор абзацев

```
Позиции:
{{#items}}
• {{name}} — {{price | number: 2}} ₽
{{/items}}
Итого: {{total}}
```

Абзацы `{{#items}}` и `{{/items}}` из результата исчезают, между ними может быть сколько угодно
абзацев, таблиц и картинок. Чтобы сработал этот режим, в абзаце с тегом не должно быть ничего,
кроме тега и пробелов.

### Повтор строк таблицы (Word, PowerPoint)

| Наименование | Кол-во | Цена |
| --- | --- | --- |
| `{{#items}}{{name}}` | `{{qty}}` | `{{price}}{{/items}}` |

### Повтор нескольких строк

Если открывающий тег стоит в одной строке таблицы, а закрывающий — в другой, повторяется
весь блок строк. Удобно для «карточек» из двух строк.

### Вложенность

Секции вкладываются друг в друга произвольно: строки таблицы внутри цикла по абзацам, условие
внутри строки таблицы и т.д. Пересекаться секции не могут — это ошибка `invalid_section`.

### `else` в циклах по абзацам и строкам

В режиме «абзацы» `{{else}}` должен стоять один в своём абзаце, в режиме «несколько строк» — один
в своей строке. В секции, повторяющей одну строку таблицы, `else` не поддерживается: вынесите
альтернативу в отдельную строку с `{{^items}}…{{/items}}`.

## 5. Условия

```
Статус: {{#if paid}}оплачено{{else}}ожидает оплаты{{/if}}
```

Для сравнений используйте фильтры:

```
{{#if total | gt: 100000}}Требуется подпись директора{{/if}}
{{#if status | eq: "paid"}}…{{/if}}
{{#if items | length | gte: 10}}Оптовая скидка{{/if}}
{{#unless client.email}}Email не указан{{/unless}}
```

Условия, как и циклы, бывают внутри абзаца, на уровне абзацев и на уровне строк таблицы —
правила те же, что в разделе 4.

## 6. Фильтры

Фильтр применяется через `|`, аргументы перечисляются после двоеточия через запятую.
Фильтры можно сцеплять:

```
{{ client.name | trim | upper }}
{{ price | number: 2, " ", "," }}
{{ comment | default: "—" | truncate: 100 }}
```

Аргументом может быть и переменная: `{{ nickname | default: fullName }}`.

### Встроенные фильтры

**Строки**

| Фильтр | Пример | Результат |
| --- | --- | --- |
| `upper`, `lower` | `{{ "Кофе" \| upper }}` | `КОФЕ` |
| `capitalize` | `{{ "иван" \| capitalize }}` | `Иван` |
| `trim` | | обрезает пробелы |
| `replace: from, to` | `{{ phone \| replace: "-", "" }}` | |
| `truncate: len, suffix` | `{{ text \| truncate: 20 }}` | обрезка с `…` |
| `prepend: s`, `append: s` | `{{ code \| prepend: "№ " }}` | только для непустых значений |
| `default: x` | `{{ phone \| default: "—" }}` | для `null`, `undefined`, `''`, `[]` |

**Числа и даты**

| Фильтр | Пример | Результат |
| --- | --- | --- |
| `number: decimals, thousands, decimal` | `{{ 1234567.891 \| number: 2 }}` | `1 234 567,89` |
| `fixed: decimals` | `{{ 3.14159 \| fixed: 2 }}` | `3.14` |
| `round: decimals` | `{{ 2.5 \| round }}` | `3` |
| `currency: code, locale, decimals` | `{{ 25 \| currency: "EUR", "de-DE" }}` | `25,00 €` |
| `percent: decimals` | `{{ 0.256 \| percent: 1 }}` | `25.6%` |
| `date: format` | `{{ d \| date: "DD.MM.YYYY HH:mm" }}` | `17.05.2024 10:00` |

Токены `date`: `YYYY YY MM M DD D HH H mm m ss s`, текст в квадратных скобках выводится как есть:
`{{ d | date: "[Москва,] DD.MM.YYYY" }}`.

**Часовой пояс.** JavaScript-`Date` — это момент времени, и по умолчанию он форматируется **в UTC**:
один и тот же шаблон даёт одинаковый результат на любом сервере. Чтобы видеть местное время,
задайте зону в настройках: `createTemplater({ timeZone: 'Europe/Moscow' })` (или `'local'` —
зона процесса). Строки дат без зоны (`"2024-05-17"`, `"2024-05-17T10:00"`) выводятся как написаны.

**Коллекции**

| Фильтр | Пример |
| --- | --- |
| `join: sep` | `{{ tags \| join: ", " }}` |
| `length`, `first`, `last`, `reverse` | `{{ items \| length }}` |
| `sort: key, dir` | `{{#each items \| sort: "price", "desc"}}` |
| `where: key, value` | `{{#each items \| where: "status", "paid"}}`; без `value` — по истинности поля |
| `slice: start, end` | `{{#each items \| slice: 0, 5}}` — первые пять |
| `json: indent` | `{{ obj \| json: 2 }}` |

**Сравнения и логика** (для условий)

`eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `not`, `and`, `or`, `contains`, `empty`, а также
`yesno: да, нет` — `{{ paid | yesno: "Оплачено", "Не оплачено" }}`.

### Свои фильтры

```ts
const templater = createTemplater({
  filters: {
    money: (value, currency = 'RUB') => `${Number(value).toFixed(2)} ${currency}`,
    plural: (n, one, few, many) => {
      const m10 = n % 10, m100 = n % 100
      if (m10 === 1 && m100 !== 11) return one
      if (m10 >= 2 && m10 <= 4 && (m100 < 10 || m100 >= 20)) return few
      return many
    },
  },
})
```

```
{{ total | money: "USD" }}
{{ count }} {{ count | plural: "товар", "товара", "товаров" }}
```

Фильтр получает значение и аргументы и возвращает любое значение — строку, число, массив, объект.
Свой фильтр с тем же именем, что у встроенного, заменяет встроенный. Неизвестный фильтр в
шаблоне — ошибка уже при `compile()`, исключение внутри фильтра превращается в `TemplateError`
с кодом `filter_failed`.

## 7. Картинки

В шаблоне — тег с `%`: `{{%logo}}`. В данных — объект `ImageValue`:

```ts
templater.render(template, {
  logo: {
    data: readFileSync('logo.png'), // Uint8Array | Buffer | ArrayBuffer | base64 | data URL
    width: 120,                      // пиксели (96 dpi), необязательно
    height: 60,                      // необязательно
    extension: 'png',                // необязательно — определяется по содержимому
    alt: 'Логотип',                  // альтернативный текст
  },
})
```

- Формат определяется автоматически: PNG, JPEG, GIF, BMP, SVG.
- Размер: если не задан — натуральный размер картинки; если задана только ширина или только
  высота — вторая сторона считается по пропорциям.
- Ложное значение (`null`, `undefined`, `false`, `''`) — картинка не вставляется, тег удаляется.

**Word.** Картинка вставляется прямо на место тега, в строку текста. Тег можно поставить
в абзац, ячейку таблицы, колонтитул или внутрь цикла.

**PowerPoint.** Поставьте `{{%logo}}` в отдельное текстовое поле или плейсхолдер. Поле целиком
заменяется картинкой, вписанной в его границы (с сохранением пропорций, по центру). У
плейсхолдеров без собственных координат берутся координаты из макета слайда.

**Excel.** Пока не поддерживается: тег-картинка в книге даёт ошибку `unsupported`.

## 8. Экранирование

**Значения из данных** всегда экранируются: `<`, `>`, `&` и кавычки в данных не могут сломать
документ или внедрить разметку. Недопустимые в XML управляющие символы удаляются.

**Разделители в тексте.** Чтобы вывести `{{` буквально, поставьте перед ним символ экранирования
(по умолчанию `\`):

| В шаблоне | В результате |
| --- | --- |
| `\{{name}}` | `{{name}}` |
| `\\{{name}}` | `\` и значение `name` |
| `C:\temp\{{file}}` | `C:\temp` и значение `file`: обратный слеш не перед разделителем не трогается |

Символ экранирования настраивается: `escapeChar: '!'`, отключается через `escapeChar: false`.

## 9. Особенности форматов

### Word (.docx)

- Обрабатываются основной текст, верхние и нижние колонтитулы, сноски и концевые сноски.
- Word часто режет текст на фрагменты (run'ы) из-за проверки орфографии, истории правок и смены
  форматирования: `{{na` + `me}}`. Библиотека склеивает такие теги автоматически. Значение получает
  форматирование того фрагмента, в котором тег **начинается**.
- Тег не может переходить из одного абзаца в другой: это ошибка `unclosed_tag`.

### Excel (.xlsx)

- Обрабатываются все листы. Строки из общей таблицы строк (`sharedStrings`), содержащие теги,
  переносятся в ячейки, остальные остаются общими.
- **Типы ячеек.** Если ячейка состоит ровно из одного тега, а значение — число или boolean, ячейка
  становится числовой или логической, и формулы с ней работают. Если вокруг тега есть текст
  (`Итого: {{sum}}`), ячейка остаётся строкой.
- **Сдвиг строк.** Когда цикл добавляет или удаляет строки, всё ниже сдвигается:
  - адреса ячеек;
  - формулы: `=SUM(D3:D3)` в строке итогов превращается в `=SUM(D3:D12)`, а формулы внутри
    повторяемой строки (`=B3*C3`) ссылаются на свою копию строки;
  - объединённые ячейки: внутри повторяемой строки они дублируются, ниже — сдвигаются;
  - условное форматирование, проверка данных, гиперссылки.
- После рендера удаляется `calcChain.xml` и выставляется пересчёт формул при открытии.

### PowerPoint (.pptx)

- Обрабатываются все слайды по порядку и заметки докладчика.
- Циклы по абзацам работают внутри одного текстового поля, циклы по строкам — в таблицах.
- Перенос строки в значении становится `<a:br>` с сохранением форматирования.
- Повтор целых слайдов пока не поддерживается.

## 10. Настройки

```ts
createTemplater({
  // Разделители тегов
  delimiters: ['{{', '}}'],          // или { start: '${', end: '}' }

  // Символ экранирования разделителей; false — отключить
  escapeChar: '\\',

  // Служебные символы и ключевые слова — всё настраивается
  syntax: {
    section: '#',    // {{#items}}
    inverted: '^',   // {{^items}}
    close: '/',      // {{/items}}
    image: '%',      // {{%logo}}
    else: 'else',    // {{else}}
    if: 'if',        // {{#if x}}
    unless: 'unless',
    each: 'each',
  },

  // Свои фильтры (добавляются к встроенным)
  filters: {},

  // Что выводить для undefined/null
  nullGetter: (tag) => '',           // tag.raw, tag.expression, tag.part

  // Бросать TemplateError('missing_value') вместо nullGetter
  strict: false,

  // \n → перенос строки, \t → табуляция (Word)
  linebreaks: true,

  // Как превращать в текст нестроковые значения
  stringify: (value) => String(value),

  // Часовой пояс для Date в данных: 'local' или IANA-имя; по умолчанию UTC
  timeZone: 'Europe/Moscow',

  // Защита от недоверенных файлов (0 — без ограничения)
  limits: {
    maxInputBytes: 100 * 1024 * 1024,   // размер файла
    maxEntries: 10_000,                 // файлов в ZIP
    maxUncompressedBytes: 500 * 1024 * 1024,
    maxCompressionRatio: 200,           // защита от zip-бомб
    maxXmlDepth: 256,
    maxOutputBytes: 500 * 1024 * 1024,  // размер результата
    maxLoopIterations: 1_000_000,       // итераций циклов за рендер
    maxHostCalls: 1_000_000,            // вызовов своих фильтров / nullGetter / stringify
  },
})
```

### Примеры разделителей

| Настройка | Теги в документе |
| --- | --- |
| `['{{', '}}']` | `{{name}}`, `{{#items}}` |
| `['${', '}']` | `${name}`, `${#items}` |
| `['[[', ']]']` | `[[name]]` |
| `['<<', '>>']` | `<<name>>` — угловые скобки в XML обрабатываются корректно |
| `['{', '}']` | `{name}` — как в docxtemplater |

### Русскоязычный синтаксис

createTemplater({ syntax: { if: 'если', else: 'иначе', each: 'для' } })

## 11. Инспекция шаблона

`inspect()` разбирает шаблон и рассказывает, какие данные ему нужны, без рендера:

```ts
const info = templater.inspect(readFileSync('invoice.docx'))
```

```ts
info.format    // 'docx'

info.variables // плоский список путей
// ['number', 'client.name', 'items[].name', 'items[].qty', 'items[].price', 'paid', 'logo']

info.schema    // пример данных нужной формы
// { number: '', client: { name: '' }, items: [{ name: '', qty: '', price: '' }], paid: true, logo: null }

info.tags      // дерево тегов: секции с детьми, выражения, фильтры, исходный текст
info.parts     // то же дерево по частям документа (тело, колонтитулы, слайды)
```

Как читать `schema`: строки — переменные, массивы — циклы, `true` — условия, `null` — картинки.

Применения:
- построить форму на фронтенде по загруженному пользователем шаблону;
- проверить, что бэкенд передаёт все нужные поля (например, сгенерировать по `schema` JSON Schema);
- показать пользователю список доступных переменных.

`{{#x}}` считается циклом, если внутри секции используются данные, и условием, если нет.
`{{#each}}` — всегда цикл.

## 12. Ошибки

Все ошибки шаблона — `TemplateError` с полями:

| Поле | Пример |
| --- | --- |
| `code` | `'unclosed_section'` |
| `tag` | `'{{#items}}'` |
| `part` | `'word/document.xml'` |
| `message` | человекочитаемое описание вместе с тегом и частью |

```ts
import { TemplateError } from 'coffee-templater'

try {
  templater.compile(file)
} catch (e) {
  if (e instanceof TemplateError) {
    return { error: e.code, tag: e.tag, part: e.part }
  }
  throw e
}
```

| Код | Причина |
| --- | --- |
| `unclosed_tag` | нет закрывающего разделителя, или тег разорван между абзацами |
| `unclosed_section` | `{{#x}}` без `{{/x}}` |
| `unmatched_close` | лишний `{{/x}}`, несовпадающее имя, `{{else}}` вне секции |
| `invalid_expression` | синтаксическая ошибка в выражении, пустой тег |
| `unknown_filter` | фильтр не существует (проверяется при компиляции) |
| `filter_failed` | фильтр бросил исключение |
| `missing_value` | нет значения в режиме `strict` |
| `invalid_section` | теги цикла в несовместимых местах, пересекающиеся секции, неверный `else` |
| `invalid_image` | значение картинки не `ImageValue` или формат не распознан |
| `unsupported` | возможность не поддерживается в этом формате (картинки в Excel) |

Ошибки уровня ядра:

| Код | Причина |
| --- | --- |
| `invalid_document` | файл не ZIP или не Office-документ, битый XML |
| `unsupported_format` | ZIP, но не docx/xlsx/pptx |
| `invalid_model` | модель для `build()` не соответствует схеме (или pptx без `base`) |
| `invalid_options` | неверные настройки: пустые или одинаковые разделители и т.п. |
| `limit_exceeded` | превышен лимит из `limits`, в `details` — какой именно |
| `host_error` | ошибка в `nullGetter` или `stringify` |
| `internal` | сбой внутри ядра — пожалуйста, создайте issue |

**Все ошибки сразу.** Если в шаблоне несколько ошибочных тегов, `compile()` сообщает обо всех:
`e.errors` — массив `{ code, message, tag, part, location, details }`, а сам `TemplateError`
описывает первую. Структурные ошибки (незакрытые секции) проверяются после того, как исправлены
ошибки в самих тегах.

Ошибки шаблона обнаруживаются при `compile()`, ошибки данных (`missing_value`, `filter_failed`,
`invalid_image`) — при `render()`.

## 13. Модель документа: parse → JSON → build

Помимо шаблонов, библиотека умеет разбирать документ в простой JSON, который удобно хранить,
передавать на фронтенд и менять в коде, а затем собирать обратно.

```ts
import { parse, build, extractText } from 'coffee-templater'

const original = readFileSync('contract.docx')
const doc = parse(original) // DocxDocument | XlsxDocument | PptxDocument

// … меняем doc …

const updated = build(doc, { base: original })
```

### Как сохраняется форматирование

Каждый абзац, фрагмент текста, ячейка и фигура хранит исходные XML-свойства в поле `props`.
Удобные поля (`bold`, `size`, `color`, `align`, …) читаются из них. При сборке поле записывается
в XML, **только если вы его изменили**, поэтому всё, что модель не описывает (интервалы, отступы,
границы, языки, эффекты), переживает цикл `parse → build` без потерь.

Удалить поле — значит снять свойство: `delete run.bold` уберёт жирность.

То, что модель не покрывает (изображения, поля, закладки, элементы управления содержимым,
отслеживаемые изменения), хранится как `{ type: 'raw', xml }` и возвращается на место как есть.

### Word — `DocxDocument`

```ts
{
  format: 'docx',
  parts: [
    {
      path: 'word/document.xml',
      kind: 'body',                       // 'body' | 'header' | 'footer'
      sectionProps: '<w:sectPr>…',        // размер страницы, поля, ссылки на колонтитулы
      blocks: [
        {
          type: 'paragraph',
          style: 'Heading1',              // id стиля абзаца
          align: 'center',                // left | center | right | justify
          list: { id: 1, level: 0 },      // нумерованный/маркированный список
          children: [
            {
              type: 'run',
              text: 'Строка 1\nСтрока 2\tпосле табуляции',
              bold: true, italic: true, underline: true, strike: false,
              color: 'FF0000', highlight: 'yellow',
              size: 14,                    // пункты
              font: 'Arial',
              vertAlign: 'superscript',
              style: 'Strong',             // id стиля символов
            },
            { type: 'hyperlink', url: 'https://example.com', children: [{ type: 'run', text: 'ссылка' }] },
            { type: 'hyperlink', anchor: 'bookmark1', children: [/* … */] },
            { type: 'break', kind: 'page' },   // 'page' | 'column'
            { type: 'raw', xml: '<w:r><w:drawing>…</w:drawing></w:r>' },
          ],
        },
        {
          type: 'table',
          rows: [
            { cells: [
              { blocks: [/* абзацы, вложенные таблицы */], colSpan: 2 },
              { blocks: [], vMerge: 'restart' },   // 'restart' | 'continue'
            ] },
          ],
        },
      ],
    },
  ],
}
```

- `\n` в тексте — перенос строки, `\t` — табуляция.
- Соседние фрагменты с одинаковым форматированием при разборе склеиваются.
- `build()` без `base` создаёт новый документ со стилями `Normal`, `Title`, `Heading1`–`Heading3`,
  `ListParagraph`, `TableGrid` (используются только части с `kind: 'body'`).

### Excel — `XlsxDocument`

```ts
{
  format: 'xlsx',
  sheets: [
    {
      name: 'Отчёт',
      path: 'xl/worksheets/sheet1.xml',   // нет path — будет создан новый лист
      merges: ['A1:D1'],
      rows: [
        {
          index: 1,                        // номер строки с 1
          height: 20,                      // пункты, если высота задана вручную
          hidden: false,
          cells: [
            { ref: 'A1', value: 'Название' },
            { ref: 'B1', value: 42, style: 3 },               // style — индекс формата ячейки
            { ref: 'C1', value: '2024-05-17', type: 'date' }, // ячейки с форматом даты
            { ref: 'D1', value: 84, formula: 'B1*2' },        // value — закэшированный результат
            { ref: 'E1', value: true },
            { ref: 'F1', value: '#DIV/0!', type: 'error' },
          ],
        },
      ],
    },
  ],
}
```

- Даты определяются по формату ячейки и отдаются ISO-строкой (`2024-05-17` или
  `2024-05-17T10:30:00Z`) с `type: 'date'`. При сборке принимаются ISO-строки и объекты `Date`;
  если у ячейки нет формата даты, он добавляется автоматически.
- Учитывается система дат 1904 (книги из старых версий Excel для Mac).
- Shared-формулы разворачиваются в обычные.
- Форматированный текст внутри ячейки (`richText`) сохраняется, пока не изменён текст.
- Листы можно переименовывать, добавлять и удалять: лист, отсутствующий в модели, удаляется.
- Ширины колонок, закрепления, фильтры, условное форматирование на существующих листах берутся
  из `base`.

#### Хелперы для импорта и экспорта

```ts
import { parseXlsxFile, sheetToObjects, sheetToArrays, sheetFromArrays, build } from 'coffee-templater'

// Импорт: загруженный файл → массив объектов по строке заголовков
const rows = sheetToObjects(parseXlsxFile(upload).sheets[0])
// [{ Название: 'Чай', Кол-во: 2 }, …]

// Заголовки во второй строке
sheetToObjects(sheet, 2)

// Двумерный массив значений
sheetToArrays(sheet) // [['Название', 'Кол-во'], ['Чай', 2]]

// Экспорт: массивы → новая книга без шаблона
const file = build({
  format: 'xlsx',
  sheets: [sheetFromArrays('Выгрузка', [['Имя', 'Дата'], ['Анна', new Date()]])],
})
```

Также экспортируются `columnToIndex('AB') → 28`, `indexToColumn(28) → 'AB'`, `parseRef('B12')`,
`serialToDate`, `dateToSerial`.

### PowerPoint — `PptxDocument`

```ts
{
  format: 'pptx',
  slides: [
    {
      path: 'ppt/slides/slide1.xml',
      notes: 'Заметки докладчика',
      shapes: [
        {
          type: 'text', id: 2, name: 'Заголовок 1', placeholder: 'title',
          paragraphs: [
            {
              align: 'center', level: 0,
              children: [{ type: 'run', text: 'Привет', bold: true, size: 40, color: '1F4E79', font: 'Arial' }],
            },
          ],
        },
        { type: 'table', id: 4, name: 'Таблица 3', rows: [{ cells: [{ paragraphs: [/* … */] }] }] },
        { type: 'picture', id: 5, name: 'Логотип' },
        // также 'group' | 'connector' | 'graphic' | 'other'
      ],
    },
  ],
}
```

- Фигуры сопоставляются с исходным файлом по `id`. Неизменяемые типы (картинки, группы, диаграммы)
  берутся из `base` как есть.
- Порядок фигур в массиве — порядок слоёв. Фигура, отсутствующая в массиве, удаляется.
- Новую фигуру можно вставить, передав её XML: `{ type: 'other', id: 99, name: 'x', xml: '<p:sp>…' }`.
- Слайды можно переупорядочивать и удалять (вместе с заметками). Дублировать слайды пока нельзя.
- В таблицы можно добавлять строки (копируется последняя строка); число колонок менять нельзя.
- Для сборки pptx обязателен `base`.

### Извлечение текста

```ts
extractText(file)      // из файла
extractText(parse(f))  // или из уже разобранной модели
```

- docx — абзацы через перенос строки, ячейки таблиц через табуляцию;
- xlsx — по каждому листу: имя и строки, ячейки через табуляцию;
- pptx — текст слайдов с разделителями `--- Slide N ---` и заметки.

Подходит для полнотекстового поиска, индексации и передачи документов в LLM.

### Express: генерация документа по запросу

import express from 'express'

const invoiceTemplate = createTemplater().compile(readFileSync('templates/invoice.docx'))

  }
})

## 15. Устройство библиотеки

```
coffee-templater (этот пакет)                 coffee-templater-engine (отдельный репозиторий)
┌───────────────────────────────┐             ┌──────────────────────────────────────────────┐
│ API: createTemplater, parse…  │   кадры     │ Rust: шаблонизатор, модель, ZIP/XML, лимиты   │
│ конвертация значений JS       │ ──────────► │ собирается в coffee_core.wasm                 │
│ свои фильтры, nullGetter      │ ◄────────── │ вызывает хост для пользовательских функций    │
└───────────────────────────────┘  callbacks  └──────────────────────────────────────────────┘
```

Код ядра в этот репозиторий **не копируется**. При сборке скрипт `scripts/fetch-engine.mjs`
скачивает готовый `coffee_core.wasm` из GitHub Release ядра нужной версии, проверяет sha256
и генерирует `src/engine/wasm-binary.ts` (в git не коммитится), а tsup встраивает его в бандл.

### Структура

```
src/
├── index.ts            публичный API
├── templater.ts        Templater / Template: compile, render, inspect, dispose; опции → ядро
├── types.ts            публичные типы: опции, теги, inspect, картинки, лимиты
├── errors.ts           TemplateError и коды ошибок
├── engine/
│   ├── core.ts         загрузка WASM, ct_alloc/ct_call, callbacks, восстановление после сбоя
│   ├── frame.ts        формат кадров "CTF1"
│   ├── values.ts       JS ↔ JSON ядра: Date, бинарные данные, bigint, часовые пояса
│   └── wasm-binary.ts  (генерируется) встроенное ядро
└── model/
    ├── index.ts        parse / build / extractText / detectFormat через ядро
    ├── types.ts        типы модели документа (DocxDocument, XlsxDocument, PptxDocument)
    ├── sheets.ts       хелперы для листов: sheetToObjects, sheetFromArrays, адреса ячеек
    └── text.ts         текст из уже разобранной модели
scripts/fetch-engine.mjs  доставка ядра
```

### Как проходит вызов

1. Обёртка сериализует запрос в JSON. JS-значения переводятся в нотацию ядра:
   `Date` → `{"$date": …}`, `Uint8Array`/`Buffer` → бинарный блоб кадра, `bigint` → число без
   потери точности. Объекты пользователя, похожие на служебные (`{"$date": …}`), экранируются.
2. Запрос упаковывается в кадр (`CTF1` + JSON + блобы), копируется в память WASM через `ct_alloc`
   и выполняется `ct_call`.
3. Если шаблону нужны свои фильтры, `nullGetter` или `stringify`, ядро синхронно вызывает
   импорт `ct_host.call`. Обёртка выполняет JS-функцию и возвращает результат кадром.
   Исключения в пользовательском коде перехватываются и становятся ошибками `filter_failed`.
4. Ответ копируется из памяти WASM и освобождается через `ct_free`. Ошибки превращаются в `TemplateError`.

### Экземпляр ядра и шаблоны

- На одну JS-среду (процесс, воркер, вкладка) — один экземпляр ядра. Он создаётся лениво
  при первом вызове.
- Скомпилированный шаблон живёт внутри экземпляра. `Template` хранит копию исходного файла и
  перекомпилирует его автоматически, если экземпляр пересоздан (`resetEngine()` или сбой ядра).
- Память шаблона освобождается `template.dispose()` или сборщиком мусора (`FinalizationRegistry`).
- Повторный вход запрещён: вызвать `render()` изнутри своего фильтра нельзя, это ошибка.
- `resetEngine()` сбрасывает экземпляр и освобождает его память. Память WebAssembly не
  уменьшается сама, поэтому после очень больших документов это может пригодиться.
- `engineInfo()` возвращает версию ядра, ABI, версию модели и sha256 встроенного бинарника.

### Откуда берётся ядро

Версия ядра закреплена в `package.json`:

```json
"coffeeEngine": { "repository": "vitJR1/coffee-templater-engine", "version": "0.1.0", "sha256": "…" }
```

- По умолчанию `npm run engine` (запускается автоматически перед `test`, `typecheck`, `build`)
  скачивает `coffee_core.wasm` из релиза `v<version>`, кэширует его в
  `node_modules/.cache/coffee-engine` и проверяет sha256.
- Для разработки ядра используйте локальную сборку:

  ```bash
  (cd ../coffee-templater-engine && make wasm)
  COFFEE_ENGINE_WASM=../coffee-templater-engine/dist/coffee_core.wasm npm test
  ```

- **Обновление ядра:** выпустите релиз в репозитории ядра (тег `vX.Y.Z`), затем поменяйте здесь
  `coffeeEngine.version` и `coffeeEngine.sha256` (sha256 файла `coffee_core.wasm` из релиза,
  он же лежит рядом в `coffee_core.wasm.sha256`).

### Прочее

- TypeScript для сборки закреплён на 5.9: генератор деклараций tsup пока не поддерживает TS 7.
- Тестовые шаблоны в `test/fixtures` создаются настоящими библиотеками Office:

  ```bash
  python -m venv .venv && .venv/bin/pip install python-docx openpyxl python-pptx
  .venv/bin/python test/fixtures/generate.py
  ```

- Для ручной проверки результатов полезно открывать их в Word / Excel / PowerPoint или LibreOffice.

### CI и релизы

- **CI** (`.github/workflows/ci.yml`): на каждый push и PR — typecheck, тесты и сборка на Node 22 и 24;
  на push в `main` дополнительно собирается `.tgz` пакета и прикладывается к запуску как артефакт.
- **Релиз** (`.github/workflows/release.yml`): запускается push'ем тега `v*`, проверяет, что тег
  совпадает с версией в `package.json`, прогоняет тесты, публикует пакет в npm и создаёт
  GitHub Release с `.tgz` и автоматическими release notes.

  ```bash
  npm version patch          # или minor / major / prerelease --preid beta
  git push --follow-tags
  ```

  Теги с суффиксом (`v1.0.0-beta.1`) публикуются в npm под dist-tag `next` и помечаются как pre-release.
  Нужен секрет репозитория `NPM_TOKEN`. Если в `package.json` есть поле `repository`, публикация
  идёт с npm provenance (подтверждённое происхождение сборки).

Оба workflow скачивают ядро из релиза, поэтому у закреплённой версии ядра должен быть GitHub Release.

## 17. Ограничения и планы

- Картинки в шаблонах Excel.
- Повтор целых слайдов PowerPoint (`{{#slides}}`).
- Excel: shared-формулы внутри повторяемых строк и диапазоны «умных таблиц» (ListObject) не сдвигаются.
- Отслеживаемые изменения и комментарии сохраняются как raw XML и не моделируются.
- Данные передаются целиком: нет асинхронных и ленивых значений, свои фильтры синхронные.
- Обёртки для Go и Python поверх того же ядра — см. спецификацию в
  [репозитории ядра](https://github.com/vitJR1/coffee-templater-engine/blob/main/docs/core-spec.md).
